# opencode-datadog-monitor Design Spec

## Overview

An OpenCode plugin that sends session, tool execution, and LLM usage data to Datadog's LLM Observability product. Similar in purpose to [opencode-sentry-monitor](https://github.com/stolinski/opencode-sentry-monitor), but using `dd-trace` with the `llmobs` module instead of `@sentry/node`.

Published to npm as `opencode-datadog-monitor`.

## Approach

Uses `dd-trace` as the sole tracing dependency. The tracer is initialized with all APM integrations disabled (`plugins: false`) and only `llmobs` enabled in agentless mode. This avoids monkey-patching Node.js internals while giving full access to the LLM Observability SDK.

The `llmobs` module handles serialization, batching, flushing, metric generation, and cost estimation. This means the plugin does not need to implement message text caching, custom metrics emission, or payload redaction — all of which the Sentry plugin does manually.

## Span Mapping

OpenCode events map to LLM Observability span kinds:

| OpenCode event | LLM Obs span kind | Lifecycle |
|---|---|---|
| `session.created` / `chat.params` | `agent` (root) | Created on first event, ended on `session.idle` |
| `tool.execute.before` / `tool.execute.after` | `tool` (child of agent) | Started before execution, ended after |
| `message.updated` (assistant, completed) | `llm` (child of agent) | Created and ended on completed assistant message |

### Span hierarchy

```
agent "opencode" (sessionID)
├── tool "bash" (callID)
├── tool "read" (callID)
├── llm "claude-sonnet-4-20250514" (messageID)
├── tool "edit" (callID)
└── llm "claude-sonnet-4-20250514" (messageID)
```

### Agent span (root)

- Created on `session.created` or `chat.params` (whichever fires first).
- Uses `sessionId` for LLM Obs conversation grouping.
- Model name and provider updated on `chat.params`.
- Ended on `session.idle`.
- Cleaned up (end + flush) on `session.deleted`.

### Tool spans

- Started on `tool.execute.before` as a child of the agent span.
- Input recorded via `llmobs.annotate({ inputData })` if `recordInputs` is enabled.
- Ended on `tool.execute.after` with output annotation if `recordOutputs` is enabled.
- Error status set if tool output indicates an error (metadata.error, status "error", or title matching /error/i).

### LLM spans

- Created on `message.updated` when an assistant message has `time.completed` set.
- Model name and provider taken from the message info.
- Token counts annotated via `llmobs.annotate({ metrics: { input_tokens, output_tokens, total_tokens } })`.
- Deduplicated by tracking completed message IDs per session to avoid re-emitting on repeated `message.updated` events.

### Error handling

- `session.error` events: log the error. If an agent span is active, annotate it with error info.
- Tool errors: detected from output metadata or title, set error status on the tool span.

## Configuration

### Config file

Loaded from the first file found in this order:

1. `OPENCODE_DD_CONFIG` environment variable (explicit path)
2. `.opencode/datadog-monitor.json` or `.opencode/datadog-monitor.jsonc` (project-level)
3. `~/.config/opencode/datadog-monitor.json` or `~/.config/opencode/datadog-monitor.jsonc` (global)

JSONC (JSON with comments) is supported via `strip-json-comments`.

### Config reference

| Field | Type | Default | Description |
|---|---|---|---|
| `site` | string | `"datadoghq.com"` | Datadog site |
| `mlApp` | string | project directory name | Application name in LLM Obs |
| `env` | string | — | Environment tag |
| `service` | string | — | Service name override |
| `recordInputs` | boolean | `true` | Record tool inputs and user messages |
| `recordOutputs` | boolean | `true` | Record tool outputs and assistant responses |
| `tags` | Record<string, string> | `{}` | Custom tags on all spans |

### Authentication

The API key is read from `DD_API_KEY` environment variable only. It is never stored in the config file. If `DD_API_KEY` is not set, the plugin logs an info message and returns empty hooks (disabled).

### Environment variable overrides

| Variable | Overrides |
|---|---|
| `DD_API_KEY` | API key (required) |
| `DD_SITE` | `site` |
| `DD_LLMOBS_ML_APP` | `mlApp` |
| `DD_ENV` | `env` |
| `DD_SERVICE` | `service` |
| `OPENCODE_DD_RECORD_INPUTS` | `recordInputs` |
| `OPENCODE_DD_RECORD_OUTPUTS` | `recordOutputs` |
| `OPENCODE_DD_TAGS` | `tags` (format: `key:value,key:value`) |

## Lifecycle

1. **Init:** Load config. Check `DD_API_KEY`. If missing, disable plugin. Initialize `dd-trace` with `plugins: false` and `llmobs: { mlApp, agentlessEnabled: true }`.
2. **Session active:** Agent span created on first session event. Tool and LLM spans created as children.
3. **Session idle:** End the agent span. Call `llmobs.flush()`. The next `chat.params` event creates a new agent span.
4. **Session deleted:** End any dangling tool spans. End agent span. Flush and clean up all state for that session.

## Plugin Hooks

The plugin exports a single `Plugin` function that returns these hooks:

- `chat.params` — update model info on the session, ensure agent span exists.
- `tool.execute.before` — start a tool span, annotate input.
- `tool.execute.after` — end the tool span, annotate output, detect errors.
- `event` — handle `session.created`, `session.idle`, `session.deleted`, `session.error`, and `message.updated`.

## Tracer Initialization

```typescript
import tracer from 'dd-trace';

tracer.init({
  llmobs: {
    mlApp: config.mlApp,
    agentlessEnabled: true,
  },
  site: config.site,
  env: config.env,
  service: config.service,
  plugins: false, // disable all APM auto-instrumentation
});

const llmobs = tracer.llmobs;
```

## State Management

Two maps track active spans:

- `sessions: Map<string, SessionState>` — maps sessionID to `{ agentSpan, providerID, modelID, completedMessages: Set<string> }`.
- `toolSpans: Map<string, Span>` — maps `${sessionID}:${callID}` to the active tool span.

Cleanup on `session.idle` ends the agent span but keeps the session state for model info. Cleanup on `session.deleted` removes all state.

## Usage

### Install

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["opencode-datadog-monitor"]
}
```

### Configure

```jsonc
// .opencode/datadog-monitor.json
{
  "site": "datadoghq.com",
  "mlApp": "my-project",
  "env": "dev",
  "tags": {
    "team": "platform",
    "developer": "adrian"
  }
}
```

### Run

```shell
DD_API_KEY=your-key opencode
```

Traces appear in the LLM Observability page at `https://app.datadoghq.com/llm/traces`.
